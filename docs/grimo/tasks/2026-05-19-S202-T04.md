# S202-T04: Production API seed helper and browser fixture migration

## 對應規格
S202：Production E2E Fixture Runner

## 這個 task 要做什麼
這個 task 完成後，`seedSkill()` 不再打 `/internal/test/seed/skill`，而是用 mock OAuth Bearer token 呼叫正式 `POST /api/v1/skills/upload`。現有 browser tests 會讀 `e2e/results/fixtures.json` 的 shared baseline，或用 production API helper 建 per-test unique skill。`rg '/internal/test' e2e/tests e2e/fixtures` 只允許 setup route absence check。

## 使用者情境（BDD）
Given（前提）mock OAuth server 可發 `developer-client` token，且 app 的 OAuth Resource Server 已啟用
When（動作）setup fixtures 呼叫 `uploadSkillFixture({ asUser: "developer", name: "docker-compose-helper" })`
Then（結果）正式 API `POST /api/v1/skills/upload` 回 201 與 `{ "id": "<uuid>" }`
And（而且）`e2e/results/fixtures.json` 有 `profiles.single.skill.id` 與 `profiles.single.skill.detailPath`
When（動作）執行 `rg '/internal/test' e2e/tests e2e/fixtures`
Then（結果）只允許 setup route absence check 檔案出現 `/internal/test/reset`
And（而且）任何 caller 都不能用 request body/query param override author

- Fixture：

- POC 跑完必須印出 `S202 T04 POC PASS`。

## 正式程式怎麼做
- 新增 `e2e/fixtures/production-api-seed.ts`
  - `tokenFor(role: "developer" | "viewer" | "admin")`
  - `uploadSkillFixture(request, input)`
  - 建立 minimal skill zip；zip 內容至少包含 `SKILL.md`
  - multipart fields 對齊 production API：`file`、`skillName`、`version`、`category`、`visibility`
  - 不傳 `author`
- 修改 `e2e/fixtures/setup.fixtures.ts`
  - seed `profiles.single.skill`
  - seed `profiles.paged.skills[]`
  - manifest names 保留：
    - `docker-compose-helper`
    - `docker-image-builder`
    - `docker-cleaner`
- 修改 `e2e/tests/_fixtures.ts`
  - 移除 `TEST_API_BASE`
  - 移除 auto reset fixture
  - export `readManifest()` / `fixtureSkill()` / production `seedSkill()`
- 修改 `e2e/tests/*.spec.ts`
  - shared read-only baseline 改讀 manifest
  - mutable/ad-hoc data 改 `seedSkill({ asUser })`
