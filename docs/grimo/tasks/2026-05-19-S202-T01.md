# S202-T01: Production artifact cleanup and forbidden route gate

## 對應規格
S202：Production E2E Fixture Runner

## 這個 task 要做什麼
這個 task 完成後，production `bootJar` 裡不會再有 `/internal/test/*` controller、E2E deterministic embedding/judge config、或 `application-e2e.yaml`。`cd backend && ./gradlew bootJar` 後掃 jar，`rg` 不會看到 `TestDataController` / `application-e2e` 等字串。這是 S202 後所有 E2E Compose 工作的前置保護，先把正式 app artifact 清乾淨。

## 使用者情境（BDD）
Given（前提）backend production source 已移除 `skill/testsupport` E2E controller/config 與 `application-e2e.yaml`
When（動作）執行 `cd backend && ./gradlew bootJar`，再執行 `jar tf build/libs/*.jar | rg 'TestDataController|SeedSkillRequest|SeedDownloadEventRequest|E2EEmbeddingConfig|E2EQualityJudgeConfig|application-e2e'`
Then（結果）`rg` 沒有任何輸出
And（而且）執行 backend test 時，原本檢查 `TestDataController` profile 的測試不再引用已刪除 class
And（而且）正式 app 啟動後，`POST /internal/test/reset` 會是 404 或 405，不是 2xx / 3xx

## 先做 POC
- POC：required — 此 task 的 POC 就是 artifact scan；必須證明 jar 內真的沒有 forbidden class/resource。
- Fixture：
  - `positive-fixture`: 目前 main source 中的 `TestDataController` / `application-e2e.yaml` → scan 應會命中，證明 detector pattern 有效
  - `negative-fixture`: 刪除後的 `bootJar` → scan 無輸出
- POC 跑完必須印出 `S202 T01 POC PASS` 或用測試/Gradle task 明確 PASS。

## 正式程式怎麼做
- 刪除 production app E2E support：
  - `backend/src/main/java/io/github/samzhu/skillshub/skill/testsupport/TestDataController.java`
  - `backend/src/main/java/io/github/samzhu/skillshub/skill/testsupport/SeedSkillRequest.java`
  - `backend/src/main/java/io/github/samzhu/skillshub/skill/testsupport/SeedDownloadEventRequest.java`

  - `backend/src/main/java/io/github/samzhu/skillshub/score/judge/E2EQualityJudgeConfig.java`
  - `backend/src/main/resources/application-e2e.yaml`
- 刪除或改寫對上述 production class 的測試，不可留下 compile error。
- 在 `backend/build.gradle.kts` 新增 artifact cleanliness check，接到 `check` 或 verify path。
- 掃描 pattern 至少包含：
  - `TestDataController`
  - `SeedSkillRequest`
  - `SeedDownloadEventRequest`
  - `E2EEmbeddingConfig`
  - `E2EQualityJudgeConfig`
  - `application-e2e`
