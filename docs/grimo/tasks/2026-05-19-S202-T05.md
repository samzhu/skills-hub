# S202-T05: Projection seed and semantic fixture data

## 對應規格
S202：Production E2E Fixture Runner

## 這個 task 要做什麼
這個 task 完成後，analytics、quality score、semantic search 這些沒有 production write API 的 read-side data，會由 `e2e/fixtures/projection-seed.ts` 經 DB guard 寫入 disposable `skillshub_e2e` DB。若 semantic E2E case 存在但缺 `SKILLSHUB_E2E_GENAI_API_KEY`，setup project 會在 seed 前 fail，錯誤訊息包含 `semantic E2E requires SKILLSHUB_E2E_GENAI_API_KEY`。

## 使用者情境（BDD）
Given（前提）setup fixtures 已用 production API 建立 `docker-compose-helper`
When（動作）projection seed helper 對該 skill 寫入 download count 5、quality score 92
Then（結果）Analytics UI 可看到 `docker-compose-helper` 與數字 `5`
And（而且）Quality UI 可看到該 skill 的固定分數資料
Given（前提）本輪包含 semantic ranking fixture 且未設定 `SKILLSHUB_E2E_GENAI_API_KEY`
When（動作）執行 `cd e2e && npx playwright test --project "setup fixtures"`
Then（結果）setup fail，錯誤訊息包含 `semantic E2E requires SKILLSHUB_E2E_GENAI_API_KEY`

## 先做 POC
- POC：required — direct SQL 只能碰 projection/read-side data，且 semantic embedding 必須跟 query provider 同一把 key。
- Fixture：
  - `positive-fixture`: guarded DB + existing skill id + downloadCount 5 → analytics API/UI 顯示 5
  - `negative-fixture`: DB guard fail 或 semantic key missing → no SQL executed，setup fail with readable message
- POC 跑完必須印出 `S202 T05 POC PASS`。

## 正式程式怎麼做
- 新增 `e2e/fixtures/projection-seed.ts`
  - `seedProjectionData(db, input)`
  - 只允許寫：
    - `download_events`
    - `skills.download_count`
    - `skill_scores`
    - `skills.embedding`
    - `skills.embedding_content`
    - `skills.embedding_model`
    - `skills.embedding_updated_at`
  - 明確禁止 direct insert aggregate tables：
    - `skills`
    - `skill_versions`
    - `skill_grants`
    - `domain_events`
    - `event_publication`
- 若 semantic fixture enabled：
  - runner 讀 `SKILLSHUB_E2E_GENAI_API_KEY`
  - 缺 key 就 throw `semantic E2E requires SKILLSHUB_E2E_GENAI_API_KEY`
  - 有 key 才對 fixture text 產生 doc embeddings 並寫入 `skills.embedding*`
- 更新 semantic browser specs：
  - 不再依賴 `E2EEmbeddingConfig`
  - 不 assert exact rank quality beyond spec 要求；只 assert semantic route、non-empty、score field、stable UI contract
