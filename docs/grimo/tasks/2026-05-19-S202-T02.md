# S202-T02: E2E production image build and Compose stack

## 對應規格
S202：Production E2E Fixture Runner

## 這個 task 要做什麼
這個 task 完成後，`cd e2e && npm run image:build` 會產生 `skillshub:e2e-local` image，且 image 內含 production frontend static app。`cd e2e && docker compose -f compose.e2e.yaml up -d --wait` 會啟動 disposable pgvector DB、mock OAuth server、app image，`curl http://localhost:8080/actuator/health` 回 `UP`。這一步把 V07 的 backend/frontend dev server target 改成 production packaged app target。

## 使用者情境（BDD）
Given（前提）T01 已讓 backend production artifact 不含 E2E support code
When（動作）執行 `cd e2e && npm run image:build`
Then（結果）`docker image inspect skillshub:e2e-local` 成功
And（而且）`git status --short backend/src/main/resources/static` 沒有輸出
When（動作）執行 `cd e2e && docker compose -f compose.e2e.yaml up -d --wait`
Then（結果）`curl http://localhost:8080/actuator/health` 回 200 且 body 包含 `UP`
And（而且）`GET http://localhost:8080/` 回 production SPA `index.html`，不是 Vite dev server HTML

  - `negative-fixture`: image 缺 static assets 或 app 仍連 localhost dev DB → health 不會滿足 S202 acceptance
- POC 跑完必須印出 `S202 T02 POC PASS`。

## 正式程式怎麼做
- `e2e/package.json`
  - 新增 `image:build`
  - 可新增 `compose:up` / `compose:down`
  - 新增需要的 dev dependency 時遵守 ecosystem-managed versions，不任意 pin downgrade
- `e2e/compose.e2e.yaml`
  - `db`: `pgvector/pgvector:pg16`，DB name `skillshub_e2e`，tmpfs storage，healthcheck `pg_isready`
  - `mock-oauth2-server`: `ghcr.io/navikt/mock-oauth2-server:3.0.1`，mount `../backend/config/oauth-mock-config.json`
  - `app`: image `${SKILLSHUB_E2E_IMAGE:-skillshub:e2e-local}`，profile `local`，DB env 指到 `db:5432/skillshub_e2e`
  - app env 必須明寫 `SKILLSHUB_SECURITY_OAUTH_ENABLED=true`、`SKILLSHUB_SECURITY_OAUTH_LOGIN_ENABLED=true`
- `e2e/.env.e2e.example`
  - 記錄 `SKILLSHUB_E2E_IMAGE`
  - 記錄 `SKILLSHUB_E2E_PORT`
  - 記錄 `SKILLSHUB_E2E_OAUTH_PORT`
- `e2e/playwright.config.ts`
  - `baseURL` 改 `http://localhost:8080`
  - `webServer` 改單一 Compose command
  - 不再啟 `npm run dev` 或 `./gradlew bootRun`
